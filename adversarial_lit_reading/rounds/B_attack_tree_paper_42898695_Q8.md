## 1. Attack Summary

**总体判断：需要重大修改**

AI-A 的决策树整体拓扑合理，对原文"非 ML 论文"的判断正确，且能区分"编码定义强迁移 / 统计主链弱迁移"。但存在以下系统性风险：

1. **证据归因过度（高）**：N2/N4 将 eICU 文本并集主张归因于 Limitations，但原文 Limitations 只说"eICU-CRD code route does not distinguish diabetes type"，并未明说 eICU 定义是"宽松"或"并集"——这是 AI-A 的引申。
2. **混淆"原文设计"与"用户任务"的边界（高）**：N7 与 N12 以"用户确认"与"工程规范"作为 evidence_location，没有原文支持。作为迁移建议可接受，但必须标注这两类节点是"用户约束"而非"论文证据"，否则读者会误判为论文支持。
3. **「死亡药效推断」措辞（中）**：N6 说"PSM+LMM 不适用"，但用户研究中若有 MIMIC 内死亡标签，30/90-day 死亡结局可能仍值得借鉴（尤其 MIMIC 有出院后死亡日期），AI-A 未区分"死亡作为预测标签"与"死亡药效对比"。
4. **「可分型」主张（中）**：N4 说 eICU 糖尿病分型"不分型"，但原文同时给出 eICU 用"250.x/E11"——若用户用 ICD 码，分型靠码本身，未必需要文本。AI-A 未区分 eICU 两种路径（文本 vs 码）。
5. **U1/U3 承认的不确定性未反映到节点**：N4 声称"主口径可照原文并集"，但原文从未给出明确的"并集"定义——需先确认冻结件是否真的采用该并集，否则 N4 是过度承诺。

## 4. Evidence Problems

**P1（高）** — N4 "eICU 宽松码路" 无原文直接证据
- AI-A 声称 eICU 文本路径"不分型→宽松"，但原文 Limitations 只说"code route does not distinguish diabetes type"，没有"宽松"的评价。
- **修正**：只引用原文 Limitations 原意，删去"宽松"等未经原文背书的价值判断；若继续用，须标注为 AI-A 推断而非原文结论。

**P2（高）** — N2/N4 混淆 eICU 两条识别路径
- 原文明确 eICU 有两条路：(1) 文本诊断（"diabetes mellitus" 或 "type 2" 且非 1 型/胰岛素依赖）；(2) 关联 ICD 码 250.x/E11。
- AI-A 的 N2/N4 把两者合并为"并集"且未指出**若走 ICD E11，分型问题消失**。
- **修正**：拆分为两个分支：路径 A（文本）→ 分型风险；路径 B（ICD）→ 分型靠码。

**P3（高）** — N11 "横断面标签" 可能过度
- 原文诊断码为 discharge diagnosis，不是 ICU 入院即刻已知。AI-A 用"横断面患病标签"可能让读者误以为"入院即已知"。
- **修正**：明确"诊断码是出院诊断，时间零点未定义；DN=1 的预测须自行定义时间零点并避免泄漏"。

**P4（中）** — N8 "canonical schema" 的迁移性被高估
- 原文的 canonical schema 能成立的前提是 MIMIC/NWICU 同查询、eICU 单独查询——用户双库结构差异更大，不能照搬。

**P5（低）** — E5 在 Evidence Map 中写"查询输出同一 canonical schema"——正确引用原文，但 Node 表中没有引用 E5 的节点。N8 引用 Section 2.1（正确），但建议加 E5 引用以强调其来源。

## 5. Missing Branches

**M1（高）— 时间零点与泄漏分支缺失**
- 用户任务：DN=1 预测。原文诊断码是 discharge diagnosis，但用户需要明确"入院时可用特征"与"出院后标签"之间的时间零点。决策树没有涵盖"预测任务的时间零点定义"这一关键分支。
- 建议新增节点 N14：**"必须定义：DN=1 判定时间零点（ICU 入院时信息 vs 住院期间出现码 vs 出院诊断）；特征与标签须从同一时间窗口抽取，防止标签泄漏"**
- 连接：N7 → N14 → N12（N14 是 N7→N12 的中间条件）。

**M2（高）— single_loop 指标可算性分支缺失**
- 用户指定 "single_loop 全可算复合指标"——决策树完全没有讨论该复合指标在 MIMIC 与 eICU 的成分可算性（如 HbA1c 在 eICU 的可用性，lab 命名差异，缺失率差异）。
- 建议新增节点 N15：**"single_loop 成分库间可算性审计：列出各成分在 MIMIC 与 eICU 的可用性/命名/缺失率；不可算成分删除或替换"**
- 连接：N7 → N15 → N12。

**M3（中）— 死亡结局缺失分支**
- 用户研究是"发病/分类预测"，但 ICU 死亡常作协助标签或灵敏度分析（如脓毒症患者死亡 vs 存活者的 DN 标签分布差）。决策树完全没有提到死亡结局在 MIMIC（有出院后死亡日期）与 eICU（无出院后死亡）的差异可用性。

**M4（中）— 赫尔辛基"诊断码无 onset"的后果未被展开**
- N11 说了 DN 是状态标签，但没有展开"状态标签 + ICU 人群=患病率可能低估/高估"（ICU 患者 T2DM 记录的灵敏度与专科门诊不同；漏诊/误诊率在两库也不同）。建议在 N11 下加分支：**"ICU 编码灵敏度差异 → 两库患病率对比作为报告内容"**。

**M5（低）— 原文"三库"与"两库"差异未被处理**

## 6. Required Fixes

**必须修改（高）**

1. **拆分 eICU 定义路径（N2/N4）**：将 eICU 的"文本路径"与"ICD 码路径"分开；只引用原文 Limitations 关于"code route 不分型"的原意，删去未经原文背书的"宽松"措辞；明确：若用户 eICU 提取走 ICD E11，则分型靠码，风险消失。
2. **N11 措辞修正**：将"横断面患病标签"改为更准确的"诊断码是出院诊断，无 onset——不可当作 ICU 入院即已知状态，更不能当作新发事件；DN=1 的预测任务须显式定义时间零点并做泄漏排除"。
3. **新增 N14（时间零点与泄漏）**：在 N7 → N14 → N12 间强制通过，确保任何迁移建议都先解决"特征窗口 / 标签窗口"定义。
4. **N2 → N3 加"同次入院 vs 历史诊断"条件**：原文 T2DM 限定"same hospital admission"，用户若放宽为"任何历史诊断"，标签口径变宽，须明确并报告。

**强烈建议（中）**

5. **新增 N15（single_loop 成分可算性审计）**：将用户指定的复合指标拆成成分表（如 HbA1c、SOFA、eGFR、Lactate 等），逐一检查在 MIMIC/eICU 的可用性与命名差异。
