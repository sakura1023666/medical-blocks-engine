## 1. Attack Summary

总体判断：**部分可信，需要重大修改**

主要问题：
- **N2 过度简化了竞争风险策略**——原文并非简单"主=CS，敏=FG"，而是 CS 与 FG 结果有实质分歧（Class 4/5 估计不同），且存在第三种 28 天死亡敏感性分析，AI-A 树未反映这一分歧。
- **N3 混淆了"暴露度量"与"建模框架"**——原文的"四套互补暴露度量"（连续、阈值、比例、累积）是 PAMM 框架内嵌的多种暴露规格；"轨迹亚型"是另一套独立建模框架（JLCMM），二者不是同层级的"暴露"，AI-A 将它们并列会导致严重的模型层级混淆。
- **N4 的证据位置与因果关系表述有误**——原文确实未报告多重比较校正，但"未报告" ≠ "未校正"；且原文用 BIC/熵/后验概率选择五类，这些是**模型选择**而非**多重比较校正**，AI-A 在节点 N4 中混谈两者。
- **N5 过度概括 Bootstrap/Permutation 的用途**——原文明确指出"模型比较用置换检验"，但 AI-A 将 Bootstrap 和置换检验捆绑表述为"内部模型比较"，实际上 Bootstrap 主要用于 CI 估计，置换检验才是模型比较。
- **N6 迁移节点缺乏原文基础**——AI-A 声称迁移至"复合指标批跑"场景，但原文是单一暴露（体温）的多层分析，不是多指标筛选，"每指标独立假设族"的表述是 AI-A 自己的设计，不能标注为"high confidence"且归因于原文推导。
- **N1 节点对原文的"单主终点"判断有因果边跳跃**——原文选择单一主终点是**为了跨库口径一致性**，但 AI-A 的决策树未标注这一关键限定条件，使得用户可能误解为"单主终点"是方法论上的最优选择，而非数据可及性驱动的妥协。
- **N3 深层的因果问题**——原文的轨迹类和 PAMM 暴露度量是同一数据集上的互补分析，**不是分层假设检验**，AI-A 将它们排列为"暴露多层并行"结构节点，隐含了"层级检验"的施工逻辑，而原文实际是"多重分析互补"逻辑。

## 4. Evidence Problems

1. **E2（Methods 2.5.5）证据引用位置正确，但被过度简化**：AI-A 引用 E2 支持 N2，但原文的 2.5.5 至少包含三层敏感性分析：① Fine-Gray 竞争风险模型；② 用 28 天全因死亡完全重跑轨迹和时变分析；③ 对连续变量用 MICE 处理缺失。AI-A 的 E2 摘要只提到①，遗漏②和③。

2. **E3（Methods 2.5.1–2.5.3）证据跨度太大**：E3 声称支持 N3 的"轨迹+PAMM+阈值负担"三层暴露结构，但 2.5.1（JLCMM 轨迹建模）、2.5.3（PAMM 时变分析）是**两个独立的分析框架**，2.5.3 内部的四种暴露度量（连续、阈值、比例、累积）是**嵌套的层面**而非并列的"层"。AI-A 将不同层级的内容统称为"多层暴露"，造成范畴混淆。

3. **E4（Results 全文结构）证据来源过泛**：AI-A 断言"原文未写 Bonferroni/FDR"，但这句话的正确表述是"原文**全文未提及**多重比较校正"。AI-A 用"Results 全文结构"作为证据位置，但事实上 E4 应更多指向 Methods 2.5.1 的模型选择段（BIC/熵/后验概率），以体现"分类数选择 ≠ HR 多重比较校正"的区分。

4. **E5（Methods 2.5.2）中"置换检验"证据被混入 Bootstrap**：E5 说"bootstrap/permutation 做模型比较"，但原文是 "Confidence intervals were estimated using bootstrap resampling with 2000 iterations, and model comparisons were performed using permutation testing with 2000 repetitions"。Bootstrap 做 CI，置换检验做模型比较，用途不同。AI-A 混用后，用户在迁移时可能将 Bootstrap 用于模型比较，导致错误的方法选择。

5. **N4 节点标称证据"原文未声明多重比较校正"与证据 E4 之间的连接链不充分**。原文确实未谈论多重比较，但缺失有两层含义：(a) 原文可能有意不为探索性分析做多重比较调整；(b) 原文可能疏漏。AI-A 未区分这两种可能性，直接断言"未声明校正"并将其作为证据节点，存在推理跳跃。

## 5. Missing Branches

1. **內部验证分割逻辑缺失**：原文明确"Model development was performed in the MIMIC-IV cohort, and external validation was conducted using the combined eICU-CRD and Nanjing Drum Tower Hospital cohorts"（2.5）。AI-A 树完全未提及"开发/验证"分割逻辑，而这一分割直接影响"多亚型/多终点"的分析可靠性——若在验证集中检验多个亚型效应，错误发现率会升高。

2. **JLCMM 前期假设分支缺失（BIC/熵联合选择五类）**：原文详细说明了类别数选择标准（BIC 最低，熵略降但可接受，类之间后验概率 >0.7，类大小 >5%），这些都是 N3 的限定条件。若迁移到其他数据集，类数可能完全不同。AI-A 树将这些重要的选择标准压缩为"五类轨迹"的事实，缺少"类别数需重新用 BIC/熵/先验选择"的条件分支。

3. **Landmark 从 landmark 到 day28 的预测窗口固定为固定时间（28天），但测量窗口取决于存活状态**：原文限定 "Patients who experienced the outcome prior to a given landmark time were excluded from the analysis at that landmark"——这一条件变量（每 landmark 处患者存活状态不同）影响 N5 的"多时点 AUC"可比性。AI-A 对此没有标注。

4. **"Class 1 / Class 2 / Class 4 / Class 5" 类间比较参照组缺失**：原文多个 HR 是相对于参照类计算的（"compared with Class 1"），且 Class 4/5 在 FG 与 CS 分析中的估计不同。AI-A 树未提供"参照类选择"的节点，也未标注"FG 与 CS 结果不一致的问题"（原文明确 Class 4/5 在两种方法下估计不同）。

5. **原始方法选择所依赖的"数据可用性"分支缺失**：原文明确 "the exact onset time of sepsis could not be reliably determined across databases, ICU admission was used as the common temporal anchor"。AI-A 树没有迁移提示：若用户数据有脓毒症发作时间，则时间定位点可以改为 sepsis onset 而非 ICU admission，这会改变轨迹与 Landmark 的定义。

## 6. Required Fixes

1. **高优先：重写 N2 以反映三层敏感性分析**，区分 CS（主）+ FG（敏感性） + 28 天全因死亡重跑全流程（敏感性），并在 N2 与 N3 之间增加"敏感性分析可能与主分析不同（详见原文 Class 4/5 在 CS/FG 中的差异）"的限定节点。

2. **高优先：拆分 N3 为两个独立的方法路径节点**（JLCMM 轨迹路径 vs PAMM 时变暴露路径），并标注 PAMM 内部的四种暴露度量是嵌套的，而非与轨迹类并列的"层"。删除"∪"聚合语义；标注"两条路径是互补分析而非同一检验层级"。

3. **高优先：删除/重新标注 N4**，区分"模型选择（BIC/熵）"与"HR 多重比较校正"两个不同问题；明确原文只报告了前者，未涉及后者。将"未报告"改为"原文未报告，亦未讨论是否进行过校正"。

4. **高优先：将 N6 从"high confidence"降为"low-medium confidence"**，并明确标注"原文未涉及多指标场景，以下为 AI-A 的设计延伸而非原文结论"。

5. **中优先：修正 N5**，区分 Bootstrap（CI 估计）与置换检验（模型比较）的不同用途；明确标注"256 个 landmark 的 AUC 不是独立检验，而是同一框架内的重复评估"。

6. **中优先：N1 节点增加限定条件**："选择 28 天院内死亡是出于跨库可比性（eICU 无院外随访）；若数据完整随访可用，则可考虑全因死亡"，并为 N1 → N2 添加分离逻辑。

7. **低优先：修正 E5 证据摘要**，将 "bootstrap/permutation 做模型比较" 改为 "Bootstrap 做 CI 估计；置换检验做模型比较（各 2000 次）"。
